# 阅读卡 · NAIK N, 2017

## 文献信息

- 著录：NAIK N, 2017. Choice of effective messaging protocols for IoT systems: MQTT, CoAP, AMQP and HTTP[C]//2017 IEEE International Systems Engineering Symposium (ISSE). Vienna: IEEE.
- 状态：已核验（IEEE ISSE 2017，DOI: 10.1109/SysEng.2017.8088251）
- 原文：IEEE Xplore 搜题名 "Choice of effective messaging protocols for IoT systems"

## 摘要要点

- 目标：帮 IoT 系统设计者在 MQTT、CoAP、AMQP、HTTP 四种应用层协议中做选型。
- 方法：对比四种协议的传输模式（发布/订阅 vs 请求/响应）、底层传输（TCP/UDP）、带宽开销、功耗、可靠性（QoS）等差异。
- 与本课题的关系：MQTT 与 HTTP 的直接对比正是这篇文章覆盖的选型问题，其中"MQTT 适合低带宽、大量设备推送，HTTP 简单通用但开销大"的结论可以作为选题依据。

## 我的阅读笔记（精读原文后填写）

### 研究问题
IoT 系统设计者在 MQTT、CoAP、AMQP、HTTP 四种主流应用层消息协议中，应该依据哪些维度选择最合适的协议。

### 方法
理论对比，从传输模式（发布/订阅 vs 请求/响应）、底层传输（TCP/UDP）、消息开销、功耗、可靠性（QoS）、安全机制和适用场景等维度逐项分析。

### 数据/环境
无实测平台，基于协议规范和已有文献结论做定性比较。

### 指标
带宽开销、消息大小、功耗、QoS 支持、连接模式、实现复杂度。

### 主要结论
MQTT 在低带宽、大量受限设备、需要服务器推送的场景下开销最小；CoAP 适合 UDP 受限网络；AMQP 面向企业级消息中间件；HTTP 最通用但轮询开销大、不适合大规模设备主动上报。

### 与本课题的关系
直接支撑"为什么选 MQTT 和 HTTP 做对比"这一选题，论文中作为选型依据引用，说明两条通道分别代表了推送和轮询两类典型机制。
