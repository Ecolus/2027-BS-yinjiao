# 实验设计文档

这份文档回答老师说的"实验设计四问"：和谁比、测什么、改什么变量、什么结果算有效。

## 一、和谁比较

**MQTT（长连接、服务端推送） vs HTTP（短连接、客户端轮询）**

在同一个 App、同一个服务端、同一个数据源下，分别走两条通道接收环境数据，对比两者的性能和可靠性差异。

## 二、测哪些指标

| 指标 | 定义 | 测量方式 |
|---|---|---|
| 端到端延迟 | 数据从数据源产生到 App 显示的时间差（ms） | 数据源打时间戳，App 收到时再打一个，取差值 |
| 消息到达率 / 丢包率 | 应收到条数 vs 实际收到条数 | 每条消息带序号，服务端统计发出数，App 统计收到数 |
| 控制指令响应时延 | App 下发指令到数据源收到的时间（ms） | App 发指令时打时间戳，数据源收到时打时间戳 |
| 断网恢复时间 | 从断网到链路自动恢复的时间（s） | 人为开关 Wi-Fi / 开飞行模式 |
| 断网期间数据是否丢失 | 恢复后是否补传断网期间的数据 | 对比断网期间数据源发出条数 vs 恢复后 App 收到条数 |

## 三、每个实验改变什么变量（控制变量）

开始对比前固定：上报频率与 HTTP 轮询间隔取同一数值；payload 大小固定；网络环境固定；服务端处理逻辑一致；MQTT 使用固定 QoS。

| 实验编号 | 改变的变量 | 固定项 | 重复次数 |
|---|---|---|---|
| EXP-00 Baseline | 无（先验证系统能用） | 局域网，1s 频率 | 跑通即可 |
| EXP-01 频率对比 | 上报频率 1s / 5s / 30s | QoS 1，固定 payload，局域网 | 每档 ≥30 次 |
| EXP-02 QoS 对照 | MQTT QoS 0 vs QoS 1 | 1s 频率，局域网 | ≥30 次 |
| EXP-03 payload 大小 | 256B vs 1KB vs 4KB | 1s 频率，QoS 1 | ≥30 次 |
| EXP-04 断网恢复 | 断网 10s / 30s / 60s | 1s 频率 | 每档 ≥5 次 |
| EXP-05 弱网 | Wi-Fi 限制带宽/延迟 | 1s 频率 | ≥30 次 |

## 四、什么结果能证明有效

- 不是笼统说"MQTT 更快"。
- 要落到具体数据：在 X 频率、Y payload、Z 网络环境下，MQTT 的延迟比 HTTP 低百分之多少；在弱网/断网场景下两者分别是什么表现；HTTP 实现简单但轮询间隔拉长会带来什么。最后给出"什么场景选 MQTT、什么场景选 HTTP"的选型建议。
- 手机耗电作为拓展指标（Android 系统级统计误差大），只作参考，不作核心结论。

## 五、四类实验清单（必须覆盖）

1. Baseline 实验（EXP-00）：证明系统能跑通。
2. 主实验（EXP-01）：MQTT vs HTTP 全频率对比。
3. 参数/消融实验（EXP-02 / EXP-03）：QoS、payload 的影响。
4. 异常/失败案例分析（EXP-04 / EXP-05）：断网、弱网下两种机制的表现。

## 六、单次实验记录模板

每个实验在 `experiments/expXX_xxx/` 下建 notes.md，按这个模板记录：

```
# Experiment ID: EXP-01
## Purpose
验证 MQTT 与 HTTP 在不同上报频率下的端到端延迟差异
## Compared with
Baseline（系统可用性）
## Configuration
- 频率：1s / 5s / 30s
- QoS：1
- payload：256B
- 网络：局域网 Wi-Fi
## Dataset
模拟数据源生成的温湿度 JSON
## Random seed
（如脚本中有随机抖动，记录 seed）
## Command
启动命令见 command.txt
## Result
结果见 metrics.csv
## Conclusion
（跑完后填）
## Problems
（跑完后填）
```
