## 1. MQTT 与 HTTP 的比较口径要公平

不能同时把"通信协议"和"交互模式（push/pull）"两个变量混在一起，还说"协议性能对比"。
- 结论统一表述为：MQTT 发布订阅机制与 HTTP 轮询机制在本系统移动物联网场景下的性能差异。
- 不写"证明 MQTT 协议优于 HTTP 协议"。
- 已改到 README、experiment_design.md。

## 2. 断网数据丢失的逻辑要分层

- 最低要求（必做）：断网—恢复后的重连时间、恢复后是否正常通信、断网期间数据是否自然丢失（不补传）。
- 拓展要求（选做）：加本地缓存/补传机制，研究能否降低数据损失。
- 已在 experiment_design.md 第四节分开写。

## 3. HTTP 不要提前写成"短连接"

OkHttp/HTTP1.1 默认复用连接、有 keep-alive。
- 主实验固定 HTTP/1.1 + Keep-Alive + 固定轮询间隔，贴近真实 App。
- "每次新建 TCP 连接"单列为 EXP-06 参数实验，不进主结论。
- 已改到 technical_route.md、experiment_design.md。
